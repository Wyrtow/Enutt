# Ролик для канала «Один герой»

Главный документ — `STYLE_BIBLE.md` в корне репозитория. **Прочитай его целиком перед началом**; все числа и запреты ниже — оттуда. Если skill и Bible расходятся, прав Bible.

Герой — **Марк** (эталон: `style_tests/HERO_sheet.png`, код персонажа: функция `hero()` в `style_tests/gen_quake.js`). Правил выживания и советов в роликах **нет** — только история.

Работа идёт по этапам. **После этапов 1, 2 и 4 остановись и покажи результат пользователю** — дальше только после «да». Генерация в ElevenLabs тратит кредиты пользователя: не перезапускай генерацию без причины.

Папка ролика: `videos/<NN>_<slug>/` (например `videos/01_zemletryasenie/`).

---

## Этап 1 — Логлайн и скелет (на согласование)
1. Тема от пользователя → 3 варианта логлайна: «Обычный день Марка → что ломается → ставка → какой поворот». Поворот должен быть неожиданным, но честно подготовленным.
2. По выбранному — **скелет** в `outline.md` по шаблону `references/outline_template.md`: крючок (тип первой фразы из Bible 2.1), деталь-обещание, 5–8 глав с названиями и клиффхэнгерами, середина-разворот, тёмный момент, поворот, 2–4 зацепки с местом setup и payoff, 1–2 выбора, второстепенные персонажи.
3. Целевая длина: пользователь называет или берём 28 мин → **~3 900 слов** (140 сл/мин).

## Этап 2 — Сценарий (на согласование)
1. Пиши `script.md` по `references/script_format.md`: текст голоса по главам + на каждый абзац разметка сцены (фон, свет, персонажи, действие, плашка, SFX, камера).
2. Самопроверка скриптом: `python3 .claude/skills/odin-geroy-video/scripts/script_stats.py videos/<...>/script.md` — слова, оценка длительности, медиана длины фразы, доля коротких фраз, «?»/«!», интервалы между битами, наличие крючка до 0:20 и аутро. Исправь всё, что вне норм Bible 2.3, до показа пользователю.
3. Покажи: крючок (первые 30 с) дословно, оглавление глав с тайм-кодами, итоговые метрики.

## Этап 3 — Озвучка (ElevenLabs, русский, с эмоциями)
Всё по `references/voice.md`. Коротко:
1. Модель **`eleven_v3` / `eleven_v4`** (только они понимают теги эмоций). Голос и модель — из `production/voice.json`; если файла нет — подбор (`creative_list_voices` / `creative_design_voice`), 2–3 пробы крючка пользователю, сравнение v3 и v4, фиксация выбора.
2. Подготовь текст для озвучки `voice_text/chNN.txt`: из `script.md` только произносимое + **аудио-теги** по таблице битов (`[nervous]`, `[whispers]`, `[gasps]`, `[sighs]`, `[pause]`…; текст русский, теги английские; смена тега раз в 2–4 фразы, не на каждой).
3. Озвучивай по главам (≤ 2 500 символов на кусок, один flow). Скачай в `audio/chNN.mp3`.
4. Пословные тайминги — `creative_transcribe_audio` → `audio/chNN.words.json` (`[{"w","s","e"}]`), сверка с текстом без тегов.
5. Склей главы в `audio/voice.wav` (48 кГц) с паузами из `voice.md`; темп 138–145 сл/мин по каждой главе.
6. Музыка (`eleven_music_v2_5`, instrumental) и SFX (`eleven_text_to_sound_v2`) — по таблице событий сценария.

## Этап 4 — Раскадровка и ключевые кадры (на согласование)
1. Из разметки сценария собери `scenes.json`: на каждую сцену — интервал по таймкодам голоса, фон, персонажи и позы, источник света и палитра, плашка (текст + цвет-смысл), события внутри плана (каждые 1–2 с), камера (наезд ~1 %/с + дрейф 5–10 px/с), переход (наплыв 10 кадров / затемнение на смене главы / жёсткая ≤ 6 %).
2. План: медиана ~9 с, первая минута — 8–11 смен.
3. Отрисуй **6–8 ключевых кадров** (крючок, каждая смена мира/локации, поворот) статикой PNG тем же кодом, что и анимацию, и покажи пользователю.

## Этап 5 — Анимация и сборка (Remotion)
1. Загрузи skill `remotion:remotion-best-practices` (и по ссылкам из него — что нужно). Проект Remotion — один на канал: `production/remotion/`. Если его нет — создай (`remotion:remotion-create`), 1920×1080, 30 fps.
2. **Камера — строго по `references/camera.md`**: multiplane-сцена (слои sky/far/mid/hero/fg на своей глубине z, параллакс = сдвиг/z, DOF-блюр по слою), каждый план ползёт (~1 %/с + дрейф), переводы smootherstep 18–40 кадров, kicks со сменой знака и затуханием 7 кадров только на событиях, реакции за 0–3 кадра до слова. Всё — функции от номера кадра (`useCurrentFrame`), никакого `Math.random()` без seed.
3. Библиотека компонентов в `production/remotion/src/lib/` — переиспользуется во всех роликах, пополняй, а не копируй:
   - `Mark` — **риг по `references/animation.md`** (перенести `style_tests/anim/rig.js`: суставы, IK ног, FK рук, поворот анфас↔¾, лицо, шарф с физикой; слои живости всегда включены; библиотека действий walk/run/startle/stop-settle/… с упреждением и доводкой). Второстепенные персонажи — тот же риг с другими пропорциями и цветами. Анимация без шагов, «скользящие» фигуры, застывшие персонажи — брак;
   - `MultiplaneCamera` + `Layer z=…` (параллакс, масштаб, DOF), `CameraPath` (ключи + smootherstep), `Kick`/`Quake` (тряска по событию), `Fog`, `Particles` (пыль/снег/пепел/искры, seed), `LightCone`, `Glow`/`Bloom`, `Vignette`, `Grade` (тон-кривая под цели Bible §4.2);
   - `KaraokeSubs` (из `words.json`, 2–5 слов, текущее слово `#ffc93a`), `Pill` (red/yellow/green/blue), `ChapterCard`, `ChoiceCard`, `PhoneInsert`, `MapInsert`, `ClockInsert`, `EndScreen` (20 с).
4. Композиция ролика `production/remotion/src/videos/<slug>.tsx` читает `scenes.json` и `words.json`, пишет `timeline.json` (планы, запланированные затемнения/вспышки, интервалы разрешённой тряски) — его читает QA.
5. **Контроль вида (look-check loop) до полного рендера**:
   - рендерь стоп-кадры (`npx remotion still … --frame=N --scale=0.5`) по 1–2 на сцену + клипы 3–5 с на каждое сложное движение камеры (`npx remotion render … --frames=a-b`);
   - смотри их сам; затем отдай 4–8 кадров **свежему агенту-проверяющему** (Agent, без контекста) вместе с `STYLE_BIBLE.md` §4 и `references/camera.md`: оценки 0–10 по «свет/цвет», «персонажи», «глубина», «композиция», «камера», «читаемость» + нумерованный список правок с номерами кадров;
   - отдельно — клипы каждого нового действия персонажей и проверка по `references/animation.md` §6 (стопы не скользят, нет рывков и застываний, «живость» ≥ 8);
   - правь, повторяй, пока все оценки ≥ 8. Результаты — в `videos/<...>/look/ROUND_N.md`.
6. Звук: `python3 .claude/skills/odin-geroy-video/scripts/mix_audio.py videos/<...>/mix.json videos/<...>/audio/mix.wav` (ducking музыки под голос, SFX, мастер −15 LUFS / −1,5 dBTP). Тайминги картинки фиксируются **до** сведения звука; любое изменение таймингов → пересвести.

## Этап 6 — Рендер и проверка качества
1. Рендер: `npx remotion render src/index.ts <Comp> out.mp4 --codec h264 --crf 16` (1920×1080, 30 fps), затем подмешать звук: `ffmpeg -i out.mp4 -i mix.wav -map 0:v:0 -map 1:a:0 -c:v copy -c:a aac -b:a 320k -ar 48000 final.mp4` (Remotion пишет немую дорожку — её не брать). Длинный рендер — в фоне; рендери по главам и склеивай (`ffmpeg concat`), чтобы падение не стоило всего ролика.
2. **Покадровая проверка**: `python3 .claude/skills/odin-geroy-video/scripts/qa_frames.py final.mp4 videos/<...>/qa videos/<...>/timeline.json` — чёрные/белые кадры, заморозки камеры, рывки, тряска вне событий, яркость/цвет/виньетка по планам против норм Bible, громкость, листы кадров. Всё с «!!» — исправить и перерендерить главу.
3. Просмотри листы кадров глазами: Марк по эталону, шарф на месте, плашки не на лицах, субтитры не вылезают, текст без опечаток.
4. Финальная проверка — свежий агент-проверяющий по листам кадров и отчёту QA.
5. Пройди чек-лист `STYLE_BIBLE.md` §6 и отчитайся по каждому пункту честно: что проверено, что нет.

## Этап 7 — Упаковка
`videos/<...>/publish.md`: 3 варианта названия, описание с тайм-кодами глав (из реальных таймингов), теги, закреплённый комментарий с вопросом о выборе. Миниатюра 1280×720 `thumbnail.png`: крупно лицо Марка с эмоцией + угроза мира + 2–4 слова, проверь читаемость в уменьшении до 320×180.

## Ловушки (из опыта)
- Remotion при каждой сборке копирует `public/` во временную папку и не удаляет — следи за диском (`df`, папки `remotion-webpack-bundle-*`), держи `public/` маленьким, ассеты — вектор/код.
- В JS-строках путей — прямые слэши (`\r` превращается в возврат каретки).
- Плёночное зерно раздувает файл в разы и превращается в кашу на YouTube: не больше 3–5 %, лучше статичная текстура, а не шум на каждый кадр.
- Длинный рендер: 1080p векторной сцены ~10–25 кадров/с → 30 мин ролика ≈ 1–3 ч. Сначала стоп-кадры и клипы, полный рендер — последним.

## Чего не делать
- Не копировать формулировки, рубрики и аутро чужих каналов (в т.ч. референса, по которому снимались замеры).
- Не вставлять правила выживания, советы, «мораль» в лоб.
- Не менять внешность Марка, голос и шарф.
- Не делать жёсткие склейки, тряску и восклицания «для динамики» — динамику дают биты сюжета и события в кадре.
- Не коммитить большие медиа (`*.mp3`, `*.wav`, `*.mp4`) в git — они в `.gitignore`; в репозитории только сценарии, код, json и PNG-эталоны.
